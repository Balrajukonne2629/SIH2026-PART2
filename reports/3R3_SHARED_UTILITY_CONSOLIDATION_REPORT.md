## 3. Shared Utility Created

Created [`ast_safety.py`](file:///c:/Users/konne%20balraju/OneDrive%20-%20Chaitanya%20Bharathi%20Institute%20of%20Technology/HACKATHONS/PART-2/ast_safety.py):
- **Single Responsibility:** Deterministic static AST code analysis for forbidden execution/socket imports.
- **Minimal API:**
  - `FORBIDDEN_EXECUTION_MODULES: Set[str]`
  - `assert_no_execution_imports(target_path: Union[str, pathlib.Path], forbidden: Optional[Set[str]] = None) -> bool`
- **Zero External Dependencies:** Built strictly on Python standard library (`ast`, `pathlib`, `typing`).
- **Zero Device Execution Capabilities:** Clean AST with 0 execution or socket imports.
- **Fail-Safe Exception Handling:** Raises `RuntimeError` on violation; raises `FileNotFoundError` if target path does not exist.

def verify_api_safety_no_execution(target_file: Optional[pathlib.Path] = None) -> bool:

## 9. Additional Duplication Intentionally Left Untouched & Why

1. **Test-Level AST Invariant Checkers** (`test_cis_benchmark.py`, `test_disa_stig.py`, `test_compliance_framework.py`):
   - **Reason**: These tests check specific framework module boundaries (e.g. asserting that `cis_benchmark_cisco_iosxe.py` contains no `requests`, `urllib`, `ollama`, or `eval/exec`). Their prohibited module sets differ intentionally based on framework scope. Keeping them in test classes preserves independent, isolated test assertions without coupling test runners to application internals.
2. **Parallel API Endpoints** (`POST /api/audit/upload` vs `POST /api/compliance/evaluate`):
   - **Reason**: Protected API contracts. `POST /api/audit/upload` is the legacy single-vendor MVP path utilized by the current React dashboard upload screen; `POST /api/compliance/evaluate` is the multi-framework engine. Harmonization is scheduled for Phase 3R.4.
3. **Password Hashing** (`database.py` vs `auth.py`):
   - **Reason**: `auth.py` already imports and reuses `database.hash_password()`. No duplication exists.
